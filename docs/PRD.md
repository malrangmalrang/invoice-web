# 노션 기반 견적서 관리 시스템 MVP PRD

## 🎯 핵심 정보

**목적**: 노션 데이터베이스를 활용하여 견적서를 관리하고, 클라이언트가 웹에서 간편하게 확인 및 PDF로 다운로드할 수 있는 시스템
**사용자**: 견적서를 발행하는 프리랜서/소규모 사업자와 견적서를 받는 클라이언트

---

## 🚶 사용자 여정

### 견적서 발행자 (관리자) 여정
1. **노션 데이터베이스**
   ↓ 견적서 데이터 입력 (노션 웹/앱에서)

2. **견적서 생성 완료**
   ↓ 노션에서 견적서 ID 확인

3. **견적서 링크 공유**
   ↓ 클라이언트에게 웹 링크 전달

### 클라이언트 여정
1. **견적서 링크 수신**
   ↓ 이메일/메신저로 받은 링크 클릭

2. **견적서 뷰어 페이지**
   ↓ 견적서 내용 확인

   [확인만 하기] → 페이지 종료
   [PDF 다운로드] → PDF 생성
   ↓

3. **PDF 다운로드 완료**
   ↓ 파일 저장 또는 인쇄

4. **완료** → 페이지 종료 또는 재확인

## ⚙️ 기술적 제약사항 및 고려사항

### Notion API 제약사항
- **Rate Limit**: 초당 3회 요청 제한 → 캐싱 전략 필요
- **응답 시간**: Notion API 호출은 1-3초 소요 → 로딩 상태 UI 필수
- **데이터 구조**: Notion 데이터베이스 스키마 변경 시 코드 수정 필요 → 유연한 파싱 로직

### PDF 생성 성능
- **react-pdf/renderer**: 경량, 빠름, 하지만 레이아웃 제약
- **jsPDF + html2canvas**: 완전한 HTML/CSS 지원, 클라이언트 사이드 생성
- **권장**: MVP는 react-pdf/renderer로 시작, 복잡한 디자인 필요 시 jsPDF로 전환

### 보안 고려사항
- **API 키 보호**: NOTION_API_KEY는 서버사이드에서만 사용 (환경변수로 관리)
- **공개 링크 방식**: 별도 인증 없이 URL만 알면 접근 가능 → 견적서 ID를 추측하기 어렵게 (노션 페이지 ID 사용)
- **선택적 보안 강화 (MVP 이후)**:
  - 일회용 토큰 방식
  - 만료 시간 설정
  - 비밀번호 보호

### 캐싱 전략
- **Next.js ISR**: 견적서 데이터를 일정 시간 캐싱하여 Notion API 호출 최소화
- **revalidate 시간**: 60초 (견적서는 자주 변경되지 않음)
- **수동 revalidation**: 노션에서 수정 후 캐시 갱신 필요 시 수동 트리거 API 제공 (선택)

## 📝 부록: Notion 데이터베이스 설정 가이드

### 1. Notion에서 데이터베이스 생성
1. Notion 워크스페이스에서 새 페이지 생성
2. `/database` 입력 후 "Table - Inline" 선택
3. 데이터베이스 이름을 "Invoices"로 설정

### 2. 필드 추가 (위 데이터 모델 참조)
- Title: `invoice_number` (견적서 번호)
- Text: `client_name`, `client_email`, `company_name` 등
- Number: `subtotal`, `vat`, `total`
- Date: `issue_date`, `expiry_date`
- Select: `status` (옵션: Draft, Sent, Approved, Rejected)

### 3. Notion Integration 생성
1. https://www.notion.so/my-integrations 접속
2. "New integration" 클릭
3. 이름 입력 후 "Submit"
4. "Internal Integration Token" 복사 → `.env.local`에 `NOTION_API_KEY`로 저장

### 4. 데이터베이스 공유 설정
1. Invoices 데이터베이스 페이지 열기
2. 우측 상단 "..." 클릭 → "Connections" → 생성한 Integration 선택
3. 데이터베이스 URL에서 ID 복사
4. `.env.local`에 `NOTION_DATABASE_ID`로 저장
